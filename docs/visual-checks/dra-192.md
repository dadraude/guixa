| Pattern                                   | Existing source                                                                                                                                                         | Decision                                                                                                                                              |

| Page headings, status, errors, controls   | `resources/js/components/Heading.vue`, `resources/js/components/InputError.vue`, `resources/js/components/ui/{badge,button,input,label}`                                | Reuse their current labels, variants, validation and action semantics. No new component was needed: the remaining forms and list rows are specific compositions of
these existing controls.

Household detail and Cycles. After manager-page form/list stacking, all six cases passed in light
and dark. A visual review at 1024 px/200% then found cramped account and household content;

passed again. The final browser sweep reports no horizontal document overflow, escaped page elements,
Vite overlay, or control below 44 × 44 px in the 173 captures. The 37 enlarged-text keyboard
cases reached their final page control (or the shell control when the page has none), with
`:focus-visible`, 2–3 px outline and horizontal/vertical visibility. Stock and return rows
retain desktop tables at normal 1280 px and reflow into labeled cards on phones and at 200%
text. Native date fields use narrower internal padding on phones so their text remains usable.
