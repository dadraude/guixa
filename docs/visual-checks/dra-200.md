# DRA-200 · T46 settings and authentication layout rules

Observed on 2026-10-28 in the DRA-200 worktree, based on `5f96548682426a082afbb6b13f9c76d5f6205327` (origin/main after PR #240). This is the T42 inventory only: three settings pages and seven authentication pages. Welcome, Dashboard and T44 are unchanged. Requests, props, validation, permissions, translations, passkey and 2FA behavior are unchanged.

## Reuse and change

The existing `AppLayout`, `settings/Layout.vue`, `AuthSimpleLayout.vue`, `Heading.vue`, `PasswordInput`, `InputError`, `TextLink`, shadcn-vue controls, and settings security components remain the composition. No new component or palette was added. The T43 panel padding value is used on each settings card: `Appearance`, `Profile`, `Security`, `DeleteUser`, `ManageTwoFactor` and `ManagePasskeys` now use `p-4 sm:p-6`. At 375 px their padding increases from 12 to 16 px, matching the settings navigation card. The 2FA challenge's OTP/error group changes from 12 to 16 px vertical spacing. The recovery-code action row now wraps when enlarged text would exceed its card. Authentication card geometry and form handling remain as before.

The visual fixture mounts the real pages and layouts from this worktree with its `resources/css/app.css` and `public/theme-colors.css`. It mocks Inertia forms, links and requests, plus 2FA and passkey transport. Browser evidence establishes layout, focus and visible states; it does not establish persistence, server authorization or a real authenticator exchange.

Both controls exceed 44 px in every case.

Other query-driven child states were checked for actual activation: Profile's delete dialog, Security's 2FA setup and confirmation dialogs, passkey removal dialog and registration form, Login's passkey error, and the 2FA challenge's recovery input. Their fixture actions and state-specific readiness or focus selectors remain in place. No other T46 state in the manifest claims a collapsed child's content.

Representative Profile, Security, Login and 2FA captures were inspected. The task-owned state fixture then reproduced Profile and Security at 375 and 2FA's error at 375/dark/200% before the changes. After the changes:

| Pattern                          | Before                                                                            | After                                                                                           | Inspection                                                                              |

| Recovery actions at 1024 px/200% | Regenerate action ended at x=1146, beyond the recovery content's x=959 right edge | The action wraps and ends at x=852, within the same content edge; 24 px separation, no overflow | Both themes pass 44 px target, clipping and keyboard checks; 1280 px/100% remains a row |

The current auth cards already had 16 px phone padding, 24 px wide padding, adequate controls and no horizontal overflow; their geometry is preserved. UI/UX Pro Max guidance matched 8 px separation between adjacent touch controls and accessible authentication with password-manager, paste and passkey paths. Its generic Vue form-library result did not apply to this presentation-only Inertia task.

## Exact retained spacing

The static check includes all ten pages, the active settings/auth layouts, `Heading.vue`, the three settings child cards, and the newly edited `TwoFactorRecoveryCodes.vue`. It guards each retained exception by exact file/class pair; any other off-grid class fails. Browser-only replacements were measured and inspected against the current UI:

| File                                    | Retained class               | Grid alternative and finding                                                                                                                                                                                                                                                                                                          |
| --------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth/Login.vue`                        | `space-x-3`                  | 12→8 px checkbox/label separation narrowed the 44 px-high label from 132 to 128 px without improving use or fit                                                                                                                                                                                                                       |
| `layouts/auth/AuthSimpleLayout.vue`     | `md:p-10`                    | 40→32 px outer padding at 1280 left the centred card unchanged; no visible benefit                                                                                                                                                                                                                                                    |
| `components/Heading.vue`                | `space-y-0.5`, `mb-0.5`      | 2→4 px made the settings header 54.2→56.2 px high and shifted following content without clearer grouping                                                                                                                                                                                                                              |
| `components/DeleteUser.vue`             | `space-y-0.5`, `space-y-3`   | 2→4 px warning and 12→16 px dialog-header gaps lengthened the card 262→264 px; the original grouping remained clearer at phone width                                                                                                                                                                                                  |
| `components/TwoFactorRecoveryCodes.vue` | `gap-3`, `mt-3`, `space-y-3` | At 200% text, changing 12 px gaps to 8 px narrowed the title/action spacing from 24 to 16 px; changing the code/note spacing to 16 px grew it from 24 to 32 px and increased the card height by 8 px at 375 and 1024. The original 24 px rhythm groups the controls and note clearly; the wrapping fix addresses the actual clipping. |

The checker also now parses `gap-x-*` before `gap-*`, so the existing valid `gap-x-1/2` utilities no longer produce false failures. The test was red on the new T46 files and parser case before those fixes, then green. This is a presentation-only T46 change: no public behavior changed, so the static layout check and rendered acceptance probes provide the test-first exception to executable behavior TDD.
