T75 (R12a, S36): the app now lets a manager send a producer order. `POST /manage/cycles/{cycle}/producers/{producer}/send` calls `SendProducerOrderManually`, a thin wrapper over `SendProducerOrder`, which gained an opt-in `refuseEmpty` flag (default behaviour unchanged). The "Send order" button lives in the producer management dialog of `Manage/Cycles/Index`, next to the cutoff actions, and asks for confirmation first because sending emails the producer. It shows only when the participant row's `canSendManually` flag is true: closed, participating, unsent and with lines to send, in a cycle that is not cancelled. Empty orders are sent by the scheduler (D10), which also validates and distributes them; a manual send of an empty order would leave it sent but never settled, so with `refuseEmpty` the use case refuses it with `ProducerOrderEmpty` under the cycle lock, after computing the totals, and the transaction rolls back. A sent order shows a Sent status on its row (`sent`). Domain errors (still open, already sent, empty, no producer account) show in the dialog. The plan's UI routes table lists the route, and the S36 traceability row cites the HTTP tests. This resolves the button deferred in the legacy log (R12a). No spec or plan rule changed, so there is no deviation.
