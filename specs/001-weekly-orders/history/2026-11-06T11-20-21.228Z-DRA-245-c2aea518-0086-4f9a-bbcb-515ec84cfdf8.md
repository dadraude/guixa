Task: DRA-245

ADR 0002 rule 5 says timestamps are stored as "ISO-8601 text in UTC". T80 stores them as `Y-m-d H:i:s.u` in UTC with no offset
(space separator, no `T`/`Z`), using Laravel's `dateTime(column, 6)` column: PostgreSQL `timestamp(6) without time zone`; on SQLite the column is declared `datetime` and the values are stored as TEXT.
The rule covers the domain `*_at` columns written through repositories; framework columns are out of scope: `timestamps()` and `failed_jobs.failed_at` are second-precision and written by Laravel, and `email_verified_at` is a second-precision framework column that the account repository writes as UTC (`Y-m-d H:i:s`), outside the `dateTime(6)` rule.
Why: it is the format Laravel's schema builder and query grammar read and write on both engines, it sorts lexically, and a
native PostgreSQL timestamp keeps range queries valid while CI still runs on PostgreSQL. The meaning of rule 5 holds: UTC,
fixed text format, converted to the cooperative's timezone at the edge. Resolved in plan.md ("Timestamp storage"). The ADR
wording ("ISO-8601", "text") may deserve a one-line clarification; docs/adr is outside T80's surfaces, so that is left to the coordinator.
