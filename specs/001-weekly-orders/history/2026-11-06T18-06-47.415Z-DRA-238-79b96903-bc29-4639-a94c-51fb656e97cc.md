# Change — Plan for the stock movement history (T76)

Draft pending the user's review; follows the accepted R28a/S93 spec change (DRA-238).

- Bounded contexts: `Stock` owns the movement history (R26–R28a).
- Ports: `Stock -> Membership AccountNames` (new Membership query `GetAccountNames`) and
  `Stock -> Ordering CyclePickupDates`.
- Stock: `ListStockMovements` defined (Manager/Finance any product, producer own via the `owns` gate);
  running balance accumulated on read from the `(occurred_at, id)`-ordered ledger, reversed and paged
  by 50; `correction` derived from adjustments with a `correctionId`; producers get no `basketId`.
  `ListStock` also serves Finance's read-only list.
- HTTP: the Manager movements page adds the history; new `/finance/stock`, `/finance/stock/{product}/movements`
  and `/producer/stock/{product}/movements`.
- D26: no stored balance, table or index; shared `components/stock/MovementHistory.vue` following
  `Wallet/Statement.vue`; paging through Laravel's `LengthAwarePaginator`.

Why: R28a needs a read model across three roles without changing the append-only ledger (R28).
