# 001 — T33 traceability audit

Evidence record for [T33 / DRA-183](weekly-and-collection.md#t33), dated 2026-11-05 and bound to `origin/main`
at `f0082fc3` (PR #312) plus the T33 test additions listed below. It audits the 65 requirements and
scenarios S1–S92 (S90 retired; 91 live scenarios) against the assertions in `tests/`, not against
identifiers: [coverage allocation](coverage.md) says who owned a rule, this file says what the tests
now prove. It marks no task or feature Done; closing feature 001 in `specs/README.md` waits for the
user's approval after exact-candidate CI.

## Method

1. Read every area spec and each scenario's Given/When/Then clauses.
2. List the tests for each rule by title and read the bodies of the multi-clause, cross-context,
   permission, history and concurrency ones. A test counts only when it asserts the clause's outcome
   at a failure boundary (rejected input leaves rows unchanged, replay writes once, a racing session
   waits and loses), through the public Application use case, the real HTTP route or the real database.
3. Check the Application layer: the constitution requires every acceptance scenario to have a use-case test. Each row below has an "Application layer" column; a row without an `Application/` test is reported "Not covered at Application layer", never plain "Covered". Feature and Integration tests supplement it.
4. Where a clause had no such assertion, add a test (no production change, accepted behavior unchanged).
5. Rule/scenario tags in test titles are a search aid only. Several scenarios are asserted by untagged
   tests (S21, S45, S81, R25c); the tables name those.

Test paths below are relative to `tests/`; `Application`, `Feature`, `Integration` and `Unit` are the
suite directories. "Covered" means every clause of the rule or scenario has an assertion.
Frontend Vue specs and the retained [visual reports](../../../docs/visual-checks/2026-10-29-reference-gates-completion.md)
cover presentation only; no requirement here depends on them alone.
