Architecture rules A1/A2/A5/A7 forced these design differences, with no behaviour change:
- Sales exposes one internal query, `ReadDashboardBasketWork::__invoke(?string $householdId = null)`, returning `DashboardBasketWorkData` (basket id, cycle id, pickup date), instead of separate `memberCollection`/`staffWork` methods (A7: Application queries expose only `__invoke`). Drafts (T03) will extend it by a separate query.
- Domain enums and `#[TypeScript]` cannot live in Dashboard Domain/Application, and controllers cannot use Dashboard Domain (A5). Application DTOs carry the action as the `ActionKind` backed string and the destination as `{staffWide, basketId}`. The controller maps them to the typed row `App\Http\AttentionGroupRow` (generated TypeScript), with a relative `href` to the existing `/baskets` or `/finance/baskets` routes. The TS enum `Guixa.Dashboard.Domain.ActionKind` is generated by the existing enum transformer.
- `Dashboard` is registered as a read-composition module (depends on Sales, Shared); Sales exports the query and DTO to it, Shared exports Actor to it.
- The superseded "Pending pickups" / "Pending collections" props and sections are removed; the `attention` prop replaces them.
